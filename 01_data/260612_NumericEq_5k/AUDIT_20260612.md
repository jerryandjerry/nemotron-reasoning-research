## The new type: ambiguous_arithmetic (560 generated, 560/560 GT-true)

All 65 originals share one mechanism: ≥2 sub-family variants (`a-b`, `b-a`, `|a-b|`, `-|a-b|`) fit
every example of the query operator but disagree on the query; the solver's ordered ~sub tie-break
(`|a-b| → a-b → -|a-b| → b-a`, lock the first match) picks one. Construction mirrors it with 4
pair-types at the measured original shares (46/32/11/9 — case4 yields negative golds, gate-safe
because its examples already demonstrate the glyph). Fillers exclude sub (the solver's
distinct-operator elimination would kill the ambiguity); gen-time gates: first-ordered-fit == pick
AND the solver's own `classify()` == ambiguous_arithmetic.

**Honest property (user-approved 2026-06-12):** for ambiguous, the gold is underdetermined by the
examples; we plant gold = our tie-break pick — the same property as the 36 orig GT-True ambiguous
(gold agrees with our pick ~52% there; we train only the agreeing kind). The CoT needs no new
wording: the ordered ~sub search already narrates these puzzles.

All 68 flags, classified and resolved:
1. *Unseen-operator acknowledged guess* (50): by design — the query operator appears only in the
   QUERY, so it is genuinely undeducible and resolved by the documented stated rule. Skeptics
   dismissed every one 0/3. 134 such puzzles exist in the original corpus.
2. *Render `}`-glyph box collision* (10 flags, 8 unique ids): **false positives, proven.** The claim
   was "the box closes early and extracts empty." Under the live `rfind('}')` extractor each box
   instead extracts the exact non-empty string the CoT wrote — `\boxed{}4}`→`}4`, `\boxed{}91}`→`}91`,
   … 8/8 recover cleanly (and 2 of the 8, e.g. NE5k_001140 `\boxed{7734}`, are plain-number boxes the
   auditor simply misread). The point is the box is *recoverable*, not that it equals gold. Same class
   as the documented `}30`/`}61` cases in ANSWER_EXTRACTION.md.
3. *Equal-operand `~sub` re-listing* (7, cosmetic): when an example has a==b the ~sub variants can't
   be disambiguated by it, so the search re-lists/defers — messy but logically correct and forward;
   the known harmless artifact noted in prior audits. Skeptics dismissed 0/3.
4. *Leading-zero narration* (1): cites the rule on a result rather than an operand; the reading is
   still correctly ruled illegal. Pre-existing solver pattern (the v3 "rule-#3-on-reversed-results"
   item), conclusion unaffected. Dismissed 0/3.

**Gold-matching is NOT the audit metric** (and not the competition metric). We planted each gold, so
"the box equals gold" is circular; it only ever served as the *selection filter* (the blind solver
recovered the planted answer → keep the puzzle). The audit metric is reasoning soundness + template
conformance + a parseable box. What the model is graded on downstream is reproducing this reasoning
trajectory, then a hidden-test extraction — neither is "matches our own gold."

**Step 5 (extractability cross-check, the render-false-positive guard):** ran the live extractor over
all 2638 → **0 boxes extract empty / NOT_FOUND**, so every learned trajectory ends in a recoverable
`\boxed{}`. **Invariants re-checked on all 2638: 0 violations** (sign-glyph==operator,
negative-gold⇒negative-example, no literal `-` with glyph ops); ambiguous 464/464 classify-consistent.
No ambiguous-specific reasoning flag appeared anywhere in the full 2638.
