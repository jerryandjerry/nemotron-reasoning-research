# How to Audit a Nemotron CoT Category — reusable 20-agent third-party audit

A repeatable process to check the quality of a generated Chain-of-Thought (CoT) corpus for ANY Nemotron
puzzle category (equation_numeric, cryptarithm, cipher, gravity, bit_manipulation, …). It was built and run
twice on equation_numeric; this doc generalizes it so another agent can apply it elsewhere.

The audit answers one question per CoT: **"Would a skeptical third party believe this reasoning, on its own?"**
— and a second, separate question: **"Does it follow the required template?"** Those are deliberately two
different audits, run by two different sets of agents, because they fail for different reasons.

---

## 0. Principles (read first — they shape everything)

1. **The CoT is the raw log of the solver — forward-only.** Every line is justified by the puzzle and the
   lines above it; no line may use a fact a later step discovers, or work backward from the answer. This is
   the #1 thing the reasoning audit checks.
2. **No answer key at inference.** A claim is sound only if it is *derived from the given examples in the
   prompt*. The reasoning auditors are given the puzzle and the CoT and **nothing else** — no template, no
   generator, no gold answer. If the CoT only makes sense because you already know the answer, it fails.
3. **GT-match is reference-only, NOT the audit target.** The audit scores *reasoning quality and template
   conformance*, not whether the boxed answer equals gold. (A CoT can be perfectly reasoned and still miss a
   gold that was generated by a different convention — see the metric cross-check.)
4. **Do not coach the auditors.** The reasoning prompt must NOT contain "here is what we fixed" / "this is
   legitimate, don't flag it." If a step is genuinely self-justifying, a naive auditor accepts it; if they
   flag it, that is the signal you want. Coaching turns the audit into a rubber stamp.
5. **The auditors don't have the scoring metric.** So any flag about *rendering* (how `\boxed{}` looks,
   whether an answer "looks broken") is suspect — you must re-check those against the real extractor
   yourself (Step 5). This is the single most common false-positive.

---

## 1. Two axes, ten agents each (why)

| axis | agents | each agent is given | judges |
|---|---|---|---|
| **Reasoning** | 10 | ONLY `question.txt` + the CoT (cold) | is the reasoning deterministic, forward-only, self-contained, internally consistent? |
| **Format** | 10 | the **template** (`cot_template.md`) + the CoT | does it conform to the required structure/wording verbatim? |

**Audit policy:** any score below 10 MUST cite the specific wrong part(s) — name the offending line(s)/text — and propose a concrete fix; a bare sub-10 score with no cited defect and no proposed solution is not a valid finding.

Why split: a reasoning auditor with the template starts checking *conformance* instead of *sense*; a format
auditor without the template can't check conformance. Keep them apart. Run all 20 in parallel as background
agents.

Scale the agent count to the corpus: ~70–75 puzzles/agent is comfortable. For 732 puzzles → 10 slices of
~73. For a much bigger or smaller set, keep ~70/agent and adjust the slice count (and the per-axis agent
count) to match.

## 2. Step-by-step

### Step 0 — the un-coached prompts (self-contained, below)
**You do not need any external file — the full reasoning prompt is Appendix A and the full format prompt is
Appendix B. Copy them and fill the placeholders.** If you want a saved copy for the record, write one into
your own category's folder. Whatever you use MUST be self-contained ("you get question.txt + the CoT, judge
if the reasoning makes sense") with NO template, NO defect-list, NO "this is fine."

### Step 1 — partition into balanced, disjoint slices
```bash
cd <CATEGORY_DIR>
ls -d <prefix>_*/ | sed 's#/##' | sort > /tmp/all.txt          # one line per puzzle dir
python3 - <<'PY'
ids=[l.strip() for l in open("/tmp/all.txt") if l.strip()]; k=10
sizes=[len(ids)//k + (1 if i<len(ids)%k else 0) for i in range(k)]; idx=0
for i in range(k):
    chunk=ids[idx:idx+sizes[i]]; idx+=sizes[i]
    open(f"/tmp/slice_{i}.txt","w").write("\n".join(chunk)+"\n")
print("sizes", sizes, "total", idx)
PY
mkdir -p /tmp/reason_results /tmp/format_results
```
Every puzzle goes to exactly one slice on each axis (full coverage, no overlap). This is **single-reviewer**
coverage — fast and broad, not redundant. If you need higher confidence on risky classes, run a second pass
with different slicing or 3 votes per puzzle on just those.

### Step 2 — launch 20 background agents
10 reasoning (Step-0 prompt, slice i, write `/tmp/reason_results/slice_i.md`) + 10 format (template + slice i,
write `/tmp/format_results/slice_i.md`). Use `general-purpose` agents, `run_in_background: true`, batched so
they run concurrently. Each reads ONLY its slice's `question.txt` + `track/tree_cot.txt` (and, for format,
`cot_template.md`) — explicitly bar the generator, instruction docs, other CoTs, and any *answer*/*gold* file
so the audit stays cold. Each writes a `| id | score | reasons |` table and returns: count, score buckets
(10 / 7-9 / 4-6 / 0-3), and the 3–5 most common issues with example ids.

### Step 3 — collect
Wait for all 20 completion notifications (don't poll). Each agent's final message gives a slice summary;
the per-puzzle detail is in its `/tmp/*_results/slice_i.md`.

**Coverage + resilience (learned the hard way).** Large parallel fan-outs **hit spend/rate limits** and
**silently drop a few ids** from a structured return (an agent reports 128 of its 132 slice ids). On
interruption, **resume** the run — completed agents return from cache instantly, only the failed slices
re-run. Before reporting, confirm each axis parses to **EXACTLY** the corpus size and **re-audit any
missing ids** (recover the returned id-set from the agent transcripts, diff against the slice). Never
report coverage you didn't actually get. For a corpus too large to cover fully, a **stratified random
sample** (category × the decorrelation axes × provenance) is a valid alternative — but label it a
sample, not full coverage.

### Step 4 — compile / aggregate
```python
import re, glob
def parse(d):
    rows={}
    for f in sorted(glob.glob(f"{d}/slice_*.md")):
        for ln in open(f, encoding="utf-8"):
            if not ln.strip().startswith("|"): continue
            p=[c.strip() for c in ln.strip().strip("|").split("|")]
            if len(p)<2: continue
            sid, m = p[0], re.search(r"\b(10|[0-9])\b", p[1])
            if not m or re.fullmatch(r"[-:\s]+", sid) or sid.lower() in ("id",""): continue
            rows[sid.replace("<prefix>_","").strip("`[]")]=int(m.group(1))
    return rows
R, F = parse("/tmp/reason_results"), parse("/tmp/format_results")
# print n, mean, score buckets, and EVERY id scored < 10 (worst first) for each axis
```
Sanity-check: each axis should parse to exactly the corpus size. List every sub-10 id — those are your
work-list.

### Step 5 — CROSS-CHECK against the real metric (kills render false-positives) ⚠️
This is the step people skip and get burned by. The auditors judge `\boxed{}` by how it *looks*, not by what
the scorer extracts. Run the **actual** extraction over the whole corpus and confirm every box is fine:
```python
import re, glob
def extract(t):                                  # the live metric: last non-empty box, close brace via rfind('}')
    bs=list(re.finditer(r'\\boxed\{',t))
    if not bs: return None
    m=bs[-1]; seg=t[m.end():]; lb=seg.rfind('}'); return (seg[:lb] if lb!=-1 else seg).strip()
bad=[f for f in glob.glob("*_*/track/tree_cot.txt") if extract(open(f).read()) in (None,"")]
print("boxes extracting empty/NOT_FOUND:", len(bad))      # expect 0
```
Because of `rfind('}')`, an answer whose operator/sign is itself a `}` renders as `\boxed{}30}` but extracts
to `}30` — **correct**. So a low score for a "broken box" is almost always a false-positive. Verify, then
discard those flags. (Cross-reference the category's answer-extraction notes / `ANSWER_EXTRACTION.md`.)

### Step 5b — deterministic conformance sweep (100% coverage, instant, no agents) ⚠️
Complement the *sampled* format agents with a grep-level pass over the **whole** corpus — it's free,
exhaustive, and catches things a sampled agent audit misses:
- **forbidden tokens absent** — the exact strings the template bans (for equation_numeric: `≠`, the word
  `fits`, ` guess`, `= unknown`); a single regression slips past sampling.
- **required fixed phrases present** and **structural markers present** (e.g. `§1`, the two-line
  `\boxed{}` ending), and the **extractor returns non-empty** for every CoT.
```python
import re, glob
BAN = ['≠', 'fits', ' guess', '= unknown']        # the template's forbidden tokens for THIS category
for f in glob.glob("*_*/track/tree_cot.txt"):
    t = open(f).read()
    for b in BAN:
        if b in t: print("FORBIDDEN", b, f)
```
This is also your **fallback for the format axis** when the agent run is blocked (spend/rate limit).
It caught a `fits` token that had slipped into a prior-knowledge line this session — a real defect the
sampled agents would not have flagged corpus-wide.

### Step 6 — triage + hand-verify the headline defects
Sort every sub-10 finding into:
- **Real reasoning defect** — a step that's asserted/guessed/circular/backward, an internal contradiction,
  or a box that disagrees with the derivation. **Read these CoTs yourself and confirm before reporting** —
  auditors are often right but sometimes wrong; never relay a "score 3" without verifying it.
- **Allowed soft pattern** — e.g. a genuinely-undeducible value resolved by a *stated, repeatable* rule
  (a deterministic guess). Per the rubric this is permitted; note it but don't treat it as a bug.
- **Cosmetic / wording** — house-style deviations the format auditors flag (a non-template phrase that's
  still unambiguous). Note; fix only if you care about verbatim conformance.
- **False-positive** — render flags killed in Step 5, or auditor misreads (they lack the generator/metric).
Expect **auditor variance**: the same situation may score 8 from one agent and 10 from another (e.g. "is a
hardcoded fallback a guess?"). That's fine — it tells you the case is a judgment call, not a hard bug.

### Step 7 — report
A short merged report: per-axis score distribution (n / mean / buckets), the deduped real defects with
example ids (linked), the soft/cosmetic patterns, and the false-positives you ruled out and why. Save it in
the category folder (e.g. `EQ data review/AUDIT_<date>.md`). Keep the un-coached prompt and this distinction
between "real" and "spurious" explicit so the next reader trusts the headline.

## 3. Gotchas / lessons (each one cost a cycle)

- **Render ≠ extraction.** The `}`/`{`-in-the-box "broken answer" is the recurring false-positive. Always
  Step 5.
- **A verification panel does NOT save you from render flags.** If you adversarially re-verify flags with N
  skeptic agents, render/`\boxed{}` flags can still be *confirmed* — a 3-skeptic panel voted 2/1 that
  `\boxed{}30}` was a broken box (they assumed balanced-brace parsing). The live `rfind('}')` extractor is
  the **sole authority**; override every render flag with it yourself, regardless of any agent vote.
- **Sampling misses corpus-wide regressions; sweep deterministically (Step 5b).** A forbidden token (e.g.
  `fits`) introduced into a shared line shows up in *every* CoT but a sampled audit only sees its slice —
  the grep sweep catches it instantly and at 100% coverage.
- **Never cite gold to validate, even in your own analysis.** "It's right because it matches the answer key"
  is meaningless at inference — judge from the examples. (And the gold may encode a *different* deterministic
  convention than yours, so a "miss" can be a tie-break difference, not a wrong CoT.)
- **Don't coach the prompt.** The moment you tell the auditor "the X behaviour is legitimate," you've lost
  the signal. If X is sound it will survive a cold read.
- **Verify headline defects by hand.** Before you act on a sub-7, read the CoT + question yourself.
- **Single-reviewer coverage is a one-pass sweep, not a proof of zero defects.** State that. For high
  assurance, add a redundant pass (3 votes) on the risky classes (exotic/unseen/ambiguous).
- **Format auditors split on house-style.** A recurring non-template phrase (e.g. a compressed reject line)
  will be flagged by some and accepted by others — decide once whether it's intentional.

## Appendix A — reasoning agent prompt (cold; fill in {CATEGORY_DESC}, {BASE}, {SLICE}, {RESULT})

> You are an independent third-party auditor reviewing a student Chain-of-Thought (CoT) for a logic puzzle.
> Judge each CoT PURELY on whether its reasoning makes sense. Judge COLD: do NOT read any solver code,
> template, instruction file, README, or other CoT. The ONLY two files you may read per puzzle are that
> puzzle's `question.txt` and its `track/tree_cot.txt`. Reading anything else (the generator, the template,
> any *review*/*LESSONS*/*AUDIT* doc, any *answer*/gold file) invalidates your audit.
>
> BASE = {BASE}. Your puzzles are listed in {SLICE}; for each `<dir>` read {BASE}/<dir>/question.txt and
> {BASE}/<dir>/track/tree_cot.txt.
>
> THE TASK THE STUDENT SOLVED (context, NOT a key): {CATEGORY_DESC}. There is NO answer key — never assume
> an answer is "correct" because it looks right; judge only the reasoning that produced it.
>
> A GOOD CoT is: **Deterministic** (every step follows by a rule, not a guess; guessing only when nothing is
> deducible and even then by a stated repeatable rule — arbitrary choice scores low); **Forward-only** (no
> line uses a fact a later step discovers, or works backward from the answer); **Self-contained** (reaches
> its answer from the puzzle alone); **Internally consistent** (no contradiction; the chain actually reaches
> the boxed answer).
>
> SCORE 0–10 as a skeptic: for EACH step, does it follow from what came before, or is it
> asserted/assumed/guessed/circular? 10 = flawless; lower for each genuine defect, naming the offending
> line. Don't nitpick wording — judge logic. OUTPUT: write {RESULT} as a `| id | score | reasons |` table
> (short id; for <10 the reason MUST name the concrete defect), then return: count reviewed, score buckets
> (10 / 7-9 / 4-6 / 0-3), and the 3–5 most serious/common issues with example ids.

## Appendix B — format agent prompt (with template; fill in {TEMPLATE}, {BASE}, {SLICE}, {RESULT})

> You are a FORMAT & WORDING conformance auditor. Check ONLY whether each CoT conforms to the required
> template — section structure, required fixed phrases, ordering conventions, lock/reject wording, and answer
> rendering. You are NOT judging whether the reasoning/math is correct (a separate audit does that).
>
> STEP 1 — read the template (the spec): {TEMPLATE}. Extract every required structural element and verbatim
> phrase, the forbidden tokens, and the answer/`\boxed{}` rendering rules.
> STEP 2 — for each puzzle in {SLICE}, read ONLY {BASE}/<dir>/question.txt and {BASE}/<dir>/track/tree_cot.txt.
> Do NOT read the generator or any other file.
>
> CHECK (format only): all required sections present & ordered; required phrases verbatim where mandated;
> forbidden tokens absent; correct answer rendering (right number of steps, correct `\boxed{}`). Do NOT
> penalize numeric values or operator deductions — only format/wording deviations. SCORE 0–10 (10 = perfect
> conformance; deduct per concrete deviation, naming it + the line). OUTPUT: write {RESULT} as
> `| id | score | deviations |`, then return: count, buckets, and the 3–5 most common deviations with ids.

## Appendix C — the metric you cross-check against
Use the live extraction: **last non-empty `\boxed{...}`, close brace found by `rfind('}')`** (so answers
containing `}` work), then `verify(gold, pred)` by the gold's shape (binary→exact, float→±1%, else→exact
string). See the category's answer-extraction notes. Run it over the whole corpus in Step 5; expect 0 boxes
to extract empty.
