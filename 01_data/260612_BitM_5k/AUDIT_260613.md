## REMEDIATED (2026-06-13, post-audit) — the "Maj/Ch hole" is fixed

The one real finding below was fixed, not just accepted. Root cause: the Pattern consistency check (PCC) only
fired when the global rule *revised* a pick; when a Maj/Ch pick was example-ambiguous but already matched the
global rule, the block was suppressed (`build_block` returns None on empty diff), so the justifying rule was
never stated and the pick read as arbitrary. Fix: `_pattern_check.build_confirm_block` + a trigger in
`_gen_bitm_faithful.gen_cot` now emit a confirm-only PCC block (existing wording: the rule line + "Positions
0 1 2 3 4 5 6 7 already match this rule.") whenever a Selected Maj/Ch position had ≥2 scan candidates and a
clean global rule exists. Template §7b updated to permit case (b). **505 puzzles** gained a confirm block;
**0 answers changed**, full-corpus box==gold re-verified (0 empty / 0 mismatch). 10 puzzles whose global rule
is a 3-term composite (NONFAM per-position labels) are left as-is — the confirm block can't cleanly state the
rule there, and forcing it would need new composite wording (not worth it for 10/5,000). Overall PCC 18%→28%
(maj 56%, ch 61% — concentrated exactly where the defect lived). The original finding follows for the record.

## Original finding (now remediated) — the "Maj/Ch hole"

19 puzzles scored 6 (slice 2) + 7 scored 7 (slice 1), concentrated entirely in the **maj/ch** paths. When an
output column is filled by a Maj or Ch function, several distinct triples often match the column equally and
**disagree on the query bit**; where no Pattern-consistency-check (PCC) fires to pin a global rule, the CoT
takes the **first match by scan order** without *stating* a tie-break. Verified (6/7 slice-1 ids have no PCC):
the pick is deterministic and GT-true (these aug puzzles passed the dual-prior gate, so scan-order == planted
rule), and every example is reproduced — but the CoT does not *justify* that triple over the equal others, so
a strict cold reader reads it as arbitrary. This is the known hole from `project_bitm_review.md`; it is a
reasoning-*justification* weakness, not a correctness defect, and an instance of the category's inherent
under-determination. Example ids: `aug_aug8b5f05c9`, `aug_aug8d75ebdc`, `aug_aug4fb92128` (pre-PCC pos6).

## Verified false positives (do NOT act on these)

1. **PCC "over-claim" (slice 2, 4 ids: `aug_aug7c7c2b5c`, `bitm_e1f3ffbb`, `bitm_06881e47`, `aug_aug21d8957d`).**
   Auditor: "claims a single rule but leaves constant-0 positions." Hand-verified FALSE: each states a clean
   positional rule (e.g. `out[i]=AND(in[i+7] (0 past the end), NOT(in[i-2]))`) that **degenerates to C0 for all
   inputs** where the shifted operand falls off the end — so `C0` at those positions *is* the rule in reduced
   form, not a coincidence. All 4 reproduce every example and box==gold. Same self-caught misread that slices 1
   & 6 reported on themselves (modular-wrap vs the CoT's stated clamp/wrap semantics).

2. **`Preferred from right` (86 of the format sub-10s).** When the right chain-walk wins, the `Selecting` block
   is emitted right-first with `Preferred from right`; template §6 documents only the left-winner orientation
   (`Preferred from left`), mirroring its own `Tentative from right`. Corpus-wide 2,978× left / 2,022× right —
   a systematic, internally-consistent generator branch. Format auditors split (scored 8–10) — house-style
   variance, not a CoT defect. **Recommend** a one-line §6 clarification documenting `Preferred from <left|right>`
   (documentation only — do NOT rewrite any CoT).

3. **`??<key>` pending render (`aug_aug3ae00865`; 585 files corpus-wide).** The pending position renders as
   `?<key>` where the key is itself a forward-reference `?N`, giving `??1`. Systematic, deterministic, present
   in 585/5,000 — the canonical nested pending-key encoding, under-documented by the template. Not a typo.

4. **Render/box flags** — none materialized; Step 5 already confirmed every box extracts correctly.

## Under-determination (universal, intrinsic — why reasoning means 9.15 not 10)

Every auditor noted the same ceiling: with ~7–10 examples vs 8 output columns and a large op library, most
query bits are not *forced* by the data — the CoT resolves them with stated, repeatable rules (PCC global rule;
longest-run left/right anchor; scan-order fallback). The rubric explicitly permits this, so it caps clean
puzzles at 9 rather than failing them. This is a property of the puzzle category (no answer key, few examples),
not of our CoT. Auditors split on the PCC: slices 6/8/9 call it a *strength* (recovers a coherent global rule);
slices 0/2/5 dock "thin-anchor" cases (a global rule induced from 2–3 anchors then applied to 5–6 positions) —
every such revision was verified to still reproduce all examples.

## Verdict

Ship-ready. No correctness defects in 700 cold-audited CoTs; 0/5,000 box-extraction problems. The only real
reasoning soft-spot is the documented Maj/Ch scan-order tie-break (maj/ch paths), inherent to the category's
under-determination. Two cosmetic template-documentation gaps (`Preferred from right`, nested `??<key>`) are
worth a one-line spec note each but require no CoT changes.

as a contradiction.

## Adversarial verification + Step-6 hand-check

707 reasoning findings ≤7 → **691 refuted** by the adversarial verifiers; **16 "confirmed-real."** Per Step 6,
all 16 were mechanically re-checked (not relayed on the agent's word):

- For **all 16**: every Selected label is truth-table-equal to what the global rule gives at that position
  (`Selected-vs-pref mismatch = ∅`), the global rule reproduces **every** example, and box==gold. So every
  "the rule is false / contradicts the AND positions" claim is a **false positive** — the verifier re-derived
  the rendered rule with wrong boundary handling or missed the degeneration. Worked example: `bitm_034fb629`
  renders `majority(in[i+2], in[i-3] (wrapping), in[i-3] (0 before the start))` — the two "in[i-3]" operands
  differ (one wraps, one clamps), so it is **not** degenerate; at position 1 it is `Maj(in3,in6,0)=AND36`,
  exactly the Selected label.
- The verifiers' *second* claim (a flagged bit is under-determined — an alternate candidate ties on the
  training data but diverges on the query) is **real but inherent**: it is resolved by the stated global rule,
  a repeatable tie-break the rubric permits, which reproduces every example. The lone no-PCC case
  `bitm_f1c1ed58` is one of the **10 documented composite-rule (T3/NONFAM) residuals** where a confirm block
  cannot be rendered — a known, pre-existing limitation, not introduced by the fix.

**Net: 0 genuine defects.** Authoritative agent-free check (run separately over the *full* corpus): all 5,000
Selected rules reproduce every example and apply-to-query == box == gold (0 contradictions, 0 box failures).

## Format

421 findings ≤7, **all** the winner-dependent `Preferred from right` / right-first `Selecting` ordering —

## Honest tradeoff surfaced by this re-audit

The fix removed the "arbitrary Maj/Ch" complaint but raised the "false PCC narrative" complaint — **both are
false positives**, but the confirm block's "all positions follow majority rule X" reads muddily when the rule
degenerates to AND/Identity at some positions. Candidate refinement (open, not yet applied): emit the confirm
block only when the global rule is **non-degenerate at all 8 positions** (every Selected label is the same
family as the rule), so the statement reads consistently; degenerate cases revert to no-confirm. Code-only,
no new wording. Pending owner decision.

## Clarity fix APPLIED (2026-06-13, post-re-audit)

Per owner directive ("if your rule is misleading, make it clear"): the confirm block no longer says only
"Positions 0-7 already match this rule" — it now spells out, per position, the rule's value in its **reduced
form** with column evidence: `Position 0: AND26 (column 010010000) matches output column 0 and is what this
rule gives at position 0.` (reuses the approved revise-line fragment). So a degenerate position — where a
majority/choice collapses to AND/Identity because a shifted operand falls off the end — reads as *what the rule
gives there*, not as a contradiction. Rolled out to all **505** confirm puzzles; **0 answers changed**, full
corpus box==gold and Selected-reproduces-every-example re-verified. Template §7b updated. This removes the
degeneration-misread surface that produced 100% of the re-audit's 16 (false-positive) "confirmed-real" flags.

**Floor for a "no score below 9" bar:** only **32/5,000 puzzles** have no statable single global rule (23
composite/NONFAM + 9 patchwork where the word solver finds none); these cannot carry a clean global-rule
justification and remain the genuinely-hard residual. The other 4,968 state the rule explicitly per position.
