# Tree CoT — Review Comments & Design Decisions

A record of every review comment that shaped the honest step-by-step CoT written to
`<puzzle>/track/tree_cot.txt` (generated by `_honest_solver.py`, reusing `cot_generator.make_prefix`
for the setup preamble and `_gen_solutions` for the answer). Current as of 2026-05-23.
See `SUMMARY.md` for the high-level report.

## 0. Integrity (non-negotiable)
- The solver derives everything from `question.txt` **only**. It never reads `answer.txt`/`label.txt`.
  Proof: regenerating with `answer.txt` deleted yields a **byte-identical** CoT.
- One deterministic solver for all puzzles — not customized per puzzle.
- The CoT is a **verbatim log of the real DFS**, emitted *during* the search (the `emit()` calls live
  inside `propagate`/`search`, co-located with the actual state mutations) — not a story narrated
  around the answer. Locks can and do backtrack (e.g. `arithmetic_05109055`), proving no foreknowledge.

## 1. Notation (tokenizer-aware: prefer 1-token, meaning-preserving)
- **Arrow:** one consistent arrow, ASCII `->` (token-equal to `→` in the Nemotron tokenizer, but more
  universal / better-represented in training).
- **Noisy operator:** `~mul` / `~add` / `~sub`. The `~` marks "noisy / approximately"; it is visually
  distinct from real `×`/`+`/`−` **and** from the real `+` inside operands like `(10H+E)`.
- **Real arithmetic** is written with `×` `+` `−` `|a-b|` (e.g. `187 = 11×17`).
- **Operators are labeled `f, g, h`** (function-call style `f(10F+A, 10J+G)`), never `x` — `x` reads as `×`.
- **Variant names are spelled out:** `add_minus1` (not `add_m1`), `mul_plus1` (not `mul_p1`),
  `absdiff_minus2` (not `absdiff_m2`). Internal names keep the abbreviations; only the display expands.
- **Answer suffix:** two lines — `I will now return the answer in \boxed{}, the answer is` then
  `\boxed{X}`. Extraction is greedy (answers can contain `}`); matches the live Kaggle metric.

## 2. Front matter — order: legend -> letter-form equations -> operator background
1. Symbol->letter legend (`" -> A`, `) -> f`).
2. **Letter-form equations first** (continues straight from the symbol assignment):
   `I will convert all the equations to letter form: EX1 ... becomes FA f JG = IIJG ...` and
   `QUERY ... becomes ...`.
3. **Then** the operator background:
   `In Alice world, multiplication, addition, subtraction and concatenating are the most common
   operations, but the results are usually noisy (off by ±1 or ±2, negated, or with operands reversed).
   For the operators in this puzzle:` then per operator, then
   `Anyway, I should analyze the pattern of the examples to figure out what they are.`
   - **`+`, `-`, `*` (strong indicators)** state the canonical meaning:
     `+, denoted as f, is usually noisy_add, but I have seen it represent [...] in other puzzles, ordered by frequency`
     (similarly `-` -> noisy_subtraction, `*` -> noisy_mul).
   - **Arbitrary symbols:** `I have seen operator f represent [noisy_add, noisy_mul, noisy_subtraction] in
     other puzzles, ordered by frequency` (families ordered by summed variant frequency; discarded ops
     gcd/lcm/mod/... dropped). If never seen: `I have not seen operator f ...`.
- The `~` shorthand is **introduced where the family is chosen** so it is never undefined:
  `Only noisy_mul survives the digit-count filter. Try f = noisy_mul. Denote it as ~mul.`
- Concat-check line: `Let me also check if operators are concat operation:` (the word "other" was removed).

## 3. Declaration & operator distinctness
- `A, B, C, ... each represent a distinct digit 0-9, leading symbol is never 0.`
- `Unknown: op f, op g. The operators are also distinct.` (distinctness clause only when >=2 arith operators)
- Distinctness is **enforced in the search** and on the **unseen-query-operator guess**, where it is
  applied at the **operation (family) level**, narrated as exclude-then-prior:
  - forced (one operation left, no prior needed):
    `Since mul and add have appeared in the puzzle, by the distinct operator rule h must be the remaining operation, noisy_subtraction.`
  - tie (two left, prior breaks it):
    `Since mul has appeared in the puzzle, by the distinct operator rule h is noisy_subtraction or noisy_add; since it is -, it is most likely noisy_subtraction.`
  - Family-level (not variant-level) matches the generator — it raised GT-match **442 -> 454 (+12)**,
    confirming operators are given distinct *operations*, not merely distinct variants.

## 4. Solver logic — faithful & eager
- Narrow ranges to a fixpoint; per equation narrow all its variables from the **same snapshot**, report once.
- All-different: cite the symbol that took each digit; detect two symbols forced to the same digit.
- **Lock an operator's variant the instant one of its examples is fully known** (operands **and** RHS) —
  eagerly, in **every** branch. Wording:
  `We now know all the operands in EX3: 11 ~mul 13, RHS = 143.` / `143 = 11×13, so lock f = mul.`
- The lock is **forced** when one variant fits the RHS; if several fit, branch and **try each**.
- After locking, the equation shows the **exact** variant (`mul`, not `~mul`) and intervals tighten to exact.
- When nothing is lockable, **branch on the least-unknown equation's variable**. Backtrack on any
  contradiction (disjoint ranges, emptied domain, digit collision).
- Reading order: standard (tens digit first); retry little-endian (units first) only if standard fails.

## 5. Answer block — five paths (in `_honest_solver.emit_answer`)
The deduction log ends with `Every equation checks: ... Solution: A = .., ...`; then one of:
1. **Concat (derived):** `Query operator g is concat_fwd (from the examples); answer = <letters> = <symbols>`.
2. **Arithmetic (derived):** `Query operator g = mul (from the examples), so QUERY is 97×39 = 3783; answer = <letters> = <symbols>`.
3. **Guess operator** (query op unseen, examples solvable): `The examples are arithmetically solvable, so
   I'll guess h is an arithmetic operator too; ...` + the §3 distinctness/prior reasoning + `Guess h = absdiff, so QUERY is |..| = ..; answer = ...`.
4. **Guess missing symbol** (answer needs a digit absent from the examples): **never emit `_`**. Print the
   full 23-symbol alphabet, then the alphabet with every used symbol masked `X`, then
   `I know the symbol-to-digit mapping is assigned uniformly at random, so none of the remaining candidates
   is more likely than another.` / `Since I have to choose, I will just take the first one that is left: 8 -> !, answer = ...`.
   (First-of-remaining is a deterministic, learnable rule; the unseen symbol is uniform — ~7% ceiling.)
5. **Blind fallback** (no arithmetic solution — usually an exotic op like gcd/mod the model doesn't cover):
   `The examples aren't arithmetically solvable; guess concat_fwd; answer = ...`.

The answer line always shows both forms: `answer = <letter-form> = <symbol-form>`, then the §1 suffix.

## 6. Verified corpus state (2026-05-23)
- 800 puzzles, 0 INVALID (every solution satisfies all examples — checked by `_verify_honest.py`).
- **GT-match: 454 / 800** (official Kaggle metric via `_build_csv.py`). By bucket: derived_arithmetic
  342/479, derived_concat 59/59, guess_operator 47/137, guess_symbol 4/78, guess_operator_and_symbol 2/19,
  blind_fallback 0/28. The non-matches are ambiguity + underivability, not bugs.
- Eager locking shrank trees ~12% vs lazy locking.
