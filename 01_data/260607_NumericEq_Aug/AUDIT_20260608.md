## The one recurring (cosmetic) finding — sign-reattach narration

The only pattern flagged on **both** axes is the negative-output rendering line:
`Need to use the operator symbol for the subtraction sign; mapping the subtraction sign g back to <SYM>, so -X -> -Y`

- **Correct and clear** when the output actually uses the operator symbol for the sign — e.g.
  [NE_aug_001279](NE_aug_001279/track/tree_cot.txt): `-63 -> }63` (gold `}63`, extractor returns `}63` ✓).
- **Confusing** when the negative renders as a literal `-` instead (the examples used literal `-`) — e.g.
  [NE_aug_000990](NE_aug_000990/track/tree_cot.txt): the line says "mapping … back to `#`, so `-31 -> -31`"
  but no `#` appears in the output. The answer (`-31`) is always correct; the narration just announces a
  remap that doesn't visibly happen.

Reasoning ids: 000990, 001210, 001211, 001226. Format ids: 001211, 001227. **Answer correct in every case.**
Optional cosmetic fix (narration only): when the negative output keeps a literal `-`, drop or reword the
"mapping … back to <SYM>" clause. Not implemented (equation_numeric CoT-wording changes are surfaced for the
user to direct, not auto-applied).
